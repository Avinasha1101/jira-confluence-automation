# Configuration Schema Documentation\n\n## Overview\n\nThe configuration schema defines all settings for the Weekly Status Report Generator. Configuration is loaded from `.claude/weekly-report-config.json` and merged with sensible defaults.\n\n**File:** `src/config/types.ts`  \n**Defaults:** `src/config/defaults.ts`  \n**Utilities:** `src/config/schema.ts`\n\n---\n\n## Complete Schema\n\n```typescript\ninterface Configuration {\n  project: ProjectConfig;\n  jira: JiraConfig;\n  confluence: ConfluenceConfig;\n  report: ReportConfig;\n}\n```\n\n---\n\n## Section 1: Project Configuration\n\n### Interface: `ProjectConfig`\n\n```typescript\ninterface ProjectConfig {\n  name: string;           // REQUIRED: Project name\n  team: string[];         // REQUIRED: Team member names\n  description?: string;   // OPTIONAL: Project description\n}\n```\n\n### Example\n\n```json\n{\n  \"project\": {\n    \"name\": \"Manager.AI\",\n    \"team\": [\"Rohit\", \"Rajiv\", \"Jagan\"],\n    \"description\": \"Automated weekly status report generator\"\n  }\n}\n```\n\n### Field Descriptions\n\n- **name** (string, REQUIRED)  \n  The project name. Used in report headers and branding.\n  - Example: \"Manager.AI\", \"CRM\", \"Analytics Platform\"\n\n- **team** (string[], REQUIRED)  \n  Array of team member names. Listed in report metadata.\n  - Example: `[\"Rohit\", \"Rajiv\", \"Jagan\"]`\n  - Minimum: 1 member\n  - Used for context only, does NOT filter Jira data\n\n- **description** (string, OPTIONAL)  \n  Optional project description for documentation.\n\n---\n\n## Section 2: Jira Configuration\n\n### Interface: `JiraConfig`\n\n```typescript\ninterface JiraConfig {\n  query_type: QueryType;                    // REQUIRED: 'sprint' or 'board'\n  sprint_id?: string;                       // CONDITIONAL: Required if query_type='sprint'\n  board_id?: string;                        // CONDITIONAL: Required if query_type='board'\n  metric_preference: MetricPreference;      // REQUIRED: 'story_points' or 'issue_count'\n  custom_fields?: {\n    story_points?: string;                  // OPTIONAL: Custom field ID (default: customfield_10016)\n    epic_link?: string;                     // OPTIONAL: Custom field ID (default: customfield_10014)\n  };\n  status_mappings: StatusMappings;          // REQUIRED: Maps Jira statuses to categories\n}\n```\n\n### Example: Sprint Mode\n\n```json\n{\n  \"jira\": {\n    \"query_type\": \"sprint\",\n    \"sprint_id\": \"123\",\n    \"metric_preference\": \"story_points\",\n    \"custom_fields\": {\n      \"story_points\": \"customfield_10016\",\n      \"epic_link\": \"customfield_10014\"\n    },\n    \"status_mappings\": {\n      \"done\": [\"Done\", \"Resolved\", \"Closed\"],\n      \"in_progress\": [\"In Progress\", \"In Review\"],\n      \"to_do\": [\"To Do\", \"Backlog\"],\n      \"blocked\": [\"Blocked\", \"On Hold\"]\n    }\n  }\n}\n```\n\n### Example: Board Mode\n\n```json\n{\n  \"jira\": {\n    \"query_type\": \"board\",\n    \"board_id\": \"456\",\n    \"metric_preference\": \"issue_count\",\n    \"status_mappings\": { ... }\n  }\n}\n```\n\n### Field Descriptions\n\n#### query_type (REQUIRED)\n\nDetermines how to fetch issues from Jira.\n\n- **\"sprint\"**  \n  Fetch issues from a specific sprint using Sprint ID.\n  - Requires: `sprint_id`\n  - Use for: Scrum teams, sprint-based delivery\n\n- **\"board\"**  \n  Fetch issues from a board's active sprint or general backlog.\n  - Requires: `board_id`\n  - Use for: Kanban teams, continuous delivery\n  - **Clarification #9:** Both options supported\n\n#### sprint_id (CONDITIONAL)\n\nJira Sprint ID. Required if `query_type=\"sprint\"`.\n\n**How to find Sprint ID:**\n1. In Jira, navigate to your board\n2. Look at the URL: `https://jira.example.com/browse/PROJ?rapidView=123&sprint=456`\n3. The sprint number is after `sprint=` → `456`\n4. Or use: `GET /rest/agile/1.0/board/123/sprint`\n\nExample: `\"sprint_id\": \"123\"`\n\n#### board_id (CONDITIONAL)\n\nJira Board ID. Required if `query_type=\"board\"`.\n\n**How to find Board ID:**\n1. In Jira, navigate to your board\n2. Look at the URL: `https://jira.example.com/browse/PROJ?rapidView=123`\n3. The board number is after `rapidView=` → `123`\n4. Or use: `GET /rest/agile/1.0/board`\n\nExample: `\"board_id\": \"123\"`\n\n#### metric_preference (REQUIRED)\n\nDetermines how to calculate completion metrics.\n\n- **\"story_points\"**  \n  Use story points for calculations.\n  - Issue must have story points assigned\n  - If ANY issue lacks points: fallback to issue count with PM confirmation\n  - **Clarification #7:** PM configures (not automatic)\n\n- **\"issue_count\"**  \n  Use number of issues (count) for calculations.\n  - Each issue counts as 1, regardless of size\n  - Useful if story points not consistently used\n\n#### custom_fields (OPTIONAL)\n\nCustom field IDs for your Jira instance. If omitted, defaults are used.\n\n**Note:** Custom field IDs vary by Jira instance. Defaults work for most Atlassian Cloud instances.\n\n**How to find custom field IDs:**\n1. In Jira, go to Settings → Issues → Custom Fields\n2. Find your field (e.g., \"Story Points\")\n3. Hover over the field name\n4. Copy the ID from the URL/tooltip: `customfield_10016`\n\n**Default Custom Fields:**\n- `story_points`: `customfield_10016` (common Atlassian default)\n- `epic_link`: `customfield_10014` (common Atlassian default)\n\n**Clarification #2:** Manual discovery acceptable. If wrong:\n- Tool logs warning\n- Falls back to issue count\n- Does NOT fail\n\n#### status_mappings (REQUIRED)\n\nMaps Jira status values to logical categories.\n\n**Interface: `StatusMappings`**\n\n```typescript\ninterface StatusMappings {\n  done: string[];           // Status values meaning \"issue is complete\"\n  in_progress: string[];    // Status values meaning \"issue is being worked on\"\n  to_do: string[];          // Status values meaning \"issue has not started\"\n  blocked: string[];        // Status values meaning \"issue is blocked\"\n}\n```\n\n**Status Category Meanings:**\n\n- **done:** Issue is complete and will not be worked on further\n  - Examples: \"Done\", \"Resolved\", \"Closed\", \"Complete\"\n\n- **in_progress:** Issue is currently being worked on\n  - Examples: \"In Progress\", \"In Development\", \"In Review\", \"QA\"\n\n- **to_do:** Issue has been planned but work has not started\n  - Examples: \"To Do\", \"Backlog\", \"Open\", \"Selected for Development\"\n\n- **blocked:** Issue cannot proceed due to dependency or blocker\n  - Examples: \"Blocked\", \"On Hold\", \"Impediment\", \"Waiting\"\n\n**Important Rules:**\n\n1. **Case-Insensitive Matching**  \n   \"Done\", \"done\", \"DONE\" all match the same category.  \n   **Clarification #4:** Case-insensitive matching required\n\n2. **No Overlapping Statuses**  \n   Each status value can appear in only ONE category.  \n   Example (INVALID): `done: [\"Resolved\"]` AND `blocked: [\"Resolved\"]`  \n   **Clarification #4:** Reject on overlap (validation error)\n\n3. **All Statuses Must Be Mapped**  \n   If Jira has a status not in any mapping, report generation fails.  \n   **Clarification #4:** Fail with list of unmapped statuses\n\n**Default Status Mappings:**\n\n```typescript\nconst DEFAULT_STATUS_MAPPINGS = {\n  done: ['Done', 'Resolved', 'Closed', 'Complete', 'Finished'],\n  in_progress: ['In Progress', 'In Development', 'In Review', 'Code Review', 'QA Review', 'Testing'],\n  to_do: ['To Do', 'Backlog', 'Open', 'Selected for Development', 'Ready', 'Planned'],\n  blocked: ['Blocked', 'Impediment', 'On Hold', 'Waiting', 'Waiting for Response'],\n};\n```\n\n---\n\n## Section 3: Confluence Configuration\n\n### Interface: `ConfluenceConfig`\n\n```typescript\ninterface ConfluenceConfig {\n  space_key: string;          // REQUIRED: Confluence space key\n  page_title: string;         // REQUIRED: Title of report page\n  parent_page_id: string;     // REQUIRED: Parent page ID for creating pages\n  page_id?: string;           // OPTIONAL: Auto-populated after first publish\n}\n```\n\n### Example\n\n```json\n{\n  \"confluence\": {\n    \"space_key\": \"MNGRAI\",\n    \"page_title\": \"Weekly Status Reports\",\n    \"parent_page_id\": \"123456\"\n  }\n}\n```\n\n### Field Descriptions\n\n#### space_key (REQUIRED)\n\nConfluence space where reports will be published.\n\n**How to find space key:**\n1. In Confluence, click on the space\n2. Look at the URL: `https://confluence.example.com/display/MNGRAI/...`\n3. The space key is after `/display/` → `MNGRAI`\n4. Or go to Space Settings → Details\n\nExample: `\"space_key\": \"MNGRAI\"`\n\n#### page_title (REQUIRED)\n\nTitle of the Confluence page where reports will be stored.\n\nNew reports will be prepended to this page. If the page doesn't exist, it will be created.\n\nExample: `\"page_title\": \"Weekly Status Reports\"`\n\n#### parent_page_id (REQUIRED)\n\nID of the parent page where the report page will be created as a child page.\n\n**How to find parent page ID:**\n1. In Confluence, open the parent page\n2. Look at the URL: `https://confluence.example.com/pages/viewpage.action?pageId=123456`\n3. The page ID is the `pageId` parameter → `123456`\n4. Or use: `GET /rest/api/content?title=PageTitle&spaceKey=KEY&expand=id`\n\n**Clarification #3:** REQUIRED for page creation. Fail with error if missing.  \n**Clarification #11:** parent_page_id is REQUIRED.\n\nExample: `\"parent_page_id\": \"123456\"`\n\n#### page_id (OPTIONAL)\n\nID of the report page. Auto-populated after the first publish.\n\nDo NOT set this manually. The system populates it after creating the page.\n\n---\n\n## Section 4: Report Configuration\n\n### Interface: `ReportConfig`\n\n```typescript\ninterface ReportConfig {\n  health_thresholds: HealthThresholds;  // REQUIRED: Health status thresholds\n  timezone?: string;                    // OPTIONAL: Timezone (default: 'UTC')\n}\n```\n\n### Example\n\n```json\n{\n  \"report\": {\n    \"health_thresholds\": {\n      \"green_max\": 10,\n      \"yellow_max\": 25\n    },\n    \"timezone\": \"America/New_York\"\n  }\n}\n```\n\n### Field Descriptions\n\n#### health_thresholds (REQUIRED)\n\nDefines when a sprint is considered \"on track\", \"at risk\", or \"blocked\" based on the percentage of blocked issues.\n\n**Interface: `HealthThresholds`**\n\n```typescript\ninterface HealthThresholds {\n  green_max: number;   // Max % for green status (5-50)\n  yellow_max: number;  // Max % for yellow status (green_max+1 to 100)\n}\n```\n\n**Health Status Calculation:**\n\n```\nblockedPercentage = (blockedIssues / totalIssues) * 100\n\nIF blockedPercentage < green_max:\n  STATUS = 🟢 Green (On Track)\nELSE IF blockedPercentage <= yellow_max:\n  STATUS = 🟡 Yellow (At Risk)\nELSE:\n  STATUS = 🔴 Red (Blocked)\n```\n\n**Constraints (Clarification #18):**\n\n- `green_max`: Must be 5-50\n- `yellow_max`: Must be greater than `green_max` and ≤ 100\n- `green_max < yellow_max` (must be strictly less than)\n\n**Examples:**\n\n```json\n{\n  \"health_thresholds\": {\n    \"green_max\": 10,\n    \"yellow_max\": 25\n  }\n}\n```\n\nMeaning:\n- Green: < 10% blocked (\"on track\")\n- Yellow: 10-25% blocked (\"at risk\")\n- Red: > 25% blocked (\"blocked\")\n\n```json\n{\n  \"health_thresholds\": {\n    \"green_max\": 5,\n    \"yellow_max\": 15\n  }\n}\n```\n\nMeaning:\n- Green: < 5% blocked (strict)\n- Yellow: 5-15% blocked\n- Red: > 15% blocked (sensitive)\n\n#### timezone (OPTIONAL)\n\nTimezone for report timestamps. All times displayed in this timezone.\n\n**Default:** `\"UTC\"`\n\n**Valid Values:** IANA timezone names\n\n**Examples:**\n- `\"America/New_York\"` (Eastern)\n- `\"America/Chicago\"` (Central)\n- `\"America/Los_Angeles\"` (Pacific)\n- `\"Europe/London\"` (GMT)\n- `\"Europe/Paris\"` (CET)\n- `\"Asia/Tokyo\"` (JST)\n- `\"Australia/Sydney\"` (AEDT)\n- `\"UTC\"` (Universal)\n\n**INVALID Values (Clarification #19):**\n\nDo NOT use abbreviations or UTC offsets:\n- ❌ `\"EST\"` (ambiguous, not IANA)\n- ❌ `\"PST\"` (ambiguous, not IANA)\n- ❌ `\"GMT\"` (ambiguous, use \"Europe/London\")\n- ❌ `\"UTC-5\"` (offset notation)\n- ❌ `\"GMT+1\"` (offset notation)\n- ❌ `\"CST\"` (Central - ambiguous, use \"America/Chicago\")\n\n**How to find correct timezone:**\n1. Visit: https://en.wikipedia.org/wiki/List_of_tz_database_time_zones\n2. Find your region in the \"TZ identifier\" column\n3. Use the identifier as-is\n\n---\n\n## Complete Configuration Example\n\n### Sprint Mode (Story Points)\n\n```json\n{\n  \"project\": {\n    \"name\": \"Manager.AI\",\n    \"team\": [\"Rohit\", \"Rajiv\", \"Jagan\"],\n    \"description\": \"CRM Team - Weekly Reports\"\n  },\n  \"jira\": {\n    \"query_type\": \"sprint\",\n    \"sprint_id\": \"123\",\n    \"metric_preference\": \"story_points\",\n    \"custom_fields\": {\n      \"story_points\": \"customfield_10016\",\n      \"epic_link\": \"customfield_10014\"\n    },\n    \"status_mappings\": {\n      \"done\": [\"Done\", \"Resolved\", \"Closed\"],\n      \"in_progress\": [\"In Progress\", \"In Review\"],\n      \"to_do\": [\"To Do\", \"Backlog\"],\n      \"blocked\": [\"Blocked\", \"On Hold\"]\n    }\n  },\n  \"confluence\": {\n    \"space_key\": \"MNGRAI\",\n    \"page_title\": \"Weekly Status Reports\",\n    \"parent_page_id\": \"123456\"\n  },\n  \"report\": {\n    \"health_thresholds\": {\n      \"green_max\": 10,\n      \"yellow_max\": 25\n    },\n    \"timezone\": \"America/New_York\"\n  }\n}\n```\n\n### Board Mode (Issue Count)\n\n```json\n{\n  \"project\": {\n    \"name\": \"Analytics\",\n    \"team\": [\"Alice\", \"Bob\"]\n  },\n  \"jira\": {\n    \"query_type\": \"board\",\n    \"board_id\": \"456\",\n    \"metric_preference\": \"issue_count\",\n    \"status_mappings\": {\n      \"done\": [\"Done\"],\n      \"in_progress\": [\"In Progress\"],\n      \"to_do\": [\"To Do\"],\n      \"blocked\": [\"Blocked\"]\n    }\n  },\n  \"confluence\": {\n    \"space_key\": \"ANALYTICS\",\n    \"page_title\": \"Weekly Reports\",\n    \"parent_page_id\": \"654321\"\n  },\n  \"report\": {\n    \"health_thresholds\": {\n      \"green_max\": 5,\n      \"yellow_max\": 15\n    }\n  }\n}\n```\n\n---\n\n## Validation Rules\n\nConfiguration is validated before use. Validation checks:\n\n✅ **Required Fields Present:**\n- project.name, project.team\n- jira.query_type, jira.status_mappings\n- confluence.space_key, confluence.page_title, confluence.parent_page_id\n- report.health_thresholds\n\n✅ **Conditional Requirements:**\n- If query_type=\"sprint\": sprint_id must be present\n- If query_type=\"board\": board_id must be present\n\n✅ **Type Validation:**\n- query_type must be \"sprint\" or \"board\"\n- metric_preference must be \"story_points\" or \"issue_count\"\n- All numeric fields must be valid numbers\n- All array fields must be arrays\n\n✅ **Value Constraints:**\n- green_max: 5-50\n- yellow_max: green_max+1 to 100\n- green_max < yellow_max (strictly)\n- timezone: valid IANA timezone (if provided)\n- status_mappings: no overlapping statuses (case-insensitive)\n- All statuses in Jira must be mapped to a category\n\n✅ **Warnings (non-blocking):**\n- Custom field IDs not found in Jira (warns, falls back to issue count)\n- Unusual health thresholds detected (warns, continues with user confirmation)\n\n---\n\n## Defaults Applied\n\nIf a field is omitted, these defaults are used:\n\n```typescript\nDEFAULT_CONFIG = {\n  jira: {\n
